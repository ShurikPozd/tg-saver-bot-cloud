# Save & Sort Bot

Личный Telegram-бот для **сохранения и умной сортировки контента**. Пересылаешь посты, картинки, альбомы и голосовые — бот сам разбирает их по категориям, папкам и тегам с помощью ИИ.

Работает 24/7: **Telegram (Telethon) → LLM (Groq) + Vision (qwen3.8) + Speech-to-Text (Whisper)**.

---

## Возможности

| Возможность | Как работает |
|---|---|
| 🗂 Авто-категоризация | ИИ понимает *о чём* контент (а не только тип файла) и создаёт/переиспользует категории: `Игры`, `Арты`, `Новости аниме`, `Продажи`… |
| 🧹 Чистка подвалов | Ссылки на каналы/чаты/ботов, «Подписаться», «private», «Предложить пост» вырезаются до распознавания — ИИ видит суть поста |
| 🖼 Анализ фото | Vision-модель описывает картинку **и читает текст на ней** (мемы, скриншоты), узнаёт игры/аниме/персонажей. Включается, когда подпись короткая или её нет |
| 🎬 Анализ видео | Кадр из ролика (ffmpeg) → vision, звуковая дорожка → Whisper. Видео без подписи больше не падают в «Видео» |
| 🎙 Распознавание голоса | Whisper транскрибирует голосовые/кружки/аудио; галлюцинации на тишине («Продолжение следует…») отбрасываются. У музыки берутся исполнитель и название |
| 🔗 Что знает Telegram | Превью ссылки, кнопки под постом, хэштеги, опросы, имя файла, место — всё идёт в подсказку ИИ |
| 🧠 Учится на архиве | В запрос добавляются похожие посты из архива и куда обычно попадает этот канал — ИИ раскладывает так же, как ты |
| 🤔 Неуверенность | Если ИИ сомневается, под сохранённым постом появляются кнопки «→ другая категория» |
| ⏳ Дораспознавание | Если Groq перегружен, пост сохраняется сразу, а распознаётся в фоне позже (и бот пишет, куда положил) |
| 🔁 Массовое перераспознавание | Идёт в фоне с паузами, тратит в основном запасную модель и оставляет половину суточного запаса qwen новым постам и расширению; на лимите ждёт и продолжает сам (переживает перезапуск), есть кнопка «Остановить» |
| 🎯 Умное перераспознавание | «🔁 Перераспознать…» предлагает взять только посты, где ИИ гадал вслепую (фото/видео без подписи без описания, «Другое»/«Фото»/«Видео»/«Заметки») — обычно втрое меньше всего архива |
| 🌙 Ночной добор | С 01:00 до 08:00 МСК бот сам дораспознаёт такие посты на остатке бесплатного лимита (к утру он восстанавливается), картинки в фоне — 512px; итог — тихим сообщением. Выключается в настройках |
| 📊 Лимиты ИИ | `/limits` или «⚙️ Настройки → 📊 Лимиты ИИ»: остаток суточного запаса каждой модели, очереди, сколько постов ждут добора |
| 📡 Правила каналов | «Канал X всегда в категорию Y»: бот предлагает правило после 3 ручных переносов, в «🛠 Сервис» — подсказки по архиву. Посты такого канала с текстом раскладываются без ИИ |
| 🖼 Похожие картинки | По «отпечатку» превью (без ИИ) замечает тот же мем/арт из другого канала, даже пережатый: подсказка при сохранении и раздел в `/dups`. Старые фото досчитываются фоном |
| 🛠 Сервис | Под категориями только частые кнопки, редкие (папки, авто-порядок, перераспознавание, теги, правила, лимиты) — в «🛠 Сервис» |
| 🧪 Проверка бэкапа | Раз в неделю (и по `/checkbackup`) бот восстанавливает свою GitHub-копию во временную базу и сверяет с живой: посты, категории, папки, теги, корзина. Не сходится — сразу пишет. Корзина тоже входит в бэкап |
| 👁 Что увидел ИИ | Кнопка в карточке поста: текст без подвалов, описание картинки/кадра, речь, превью ссылки — видно, почему пост лёг именно туда |
| 🔍 Поиск | Без учёта регистра и по всем словам запроса, в том числе по тому, что ИИ увидел на картинках |
| 📊 Кто тратит лимит | В `/limits` — расход за сутки по источникам: новые посты, фон, дораспознавание, расширение YouTube, сервисные функции |
| ☁️ Запасной ИИ | Если у обеих моделей Groq кончился суточный запас, новые посты раскладывает Cloudflare Workers AI (бесплатно, 10 000 «нейронов» в сутки, переменные `CF_ACCOUNT_ID` и `CF_API_TOKEN`). Фоновый добор его не трогает |
| 🧩 Папки и подпапки | Автоматически раскладывает по темам (`Игры/PS5`, `Кино/Marvel`) и создаёт подпапки при накоплении похожих постов |
| 🏷 Теги | Гибкая система тегов с иконками для перекрёстного поиска |
| 🔁 Защита от дублей | Проверяет, что фото/видео/текст ещё не сохранялись |
| 🔒 Автозамок | Ручные правки не смазываются автоматическим пересортированием |
| 🔍 Поиск | По тексту, тегам и дате |
| 🗑 Корзина | Удаление с отменой и безвозвратным далением |
| 📊 Статистика и дайджест | Сколько и чего сохранено; еженедельный обзор |
| 💾 Экспорт / бэкап | Полный экспорт архива (gzip) + автоматическая страховка в GitHub-синк и seed-файл (копия в канал-хранилище — по ручному `/export`) |
| 👥 Мультиюзер | У каждого пользователя свой изолированный архив, категории и настройки |

## Стек

- **Telegram**: Telethon (SOCKS5 через Xray 127.0.0.1:10808 — основной, MTProxy-резерв)
- **ИИ**: Groq API — `qwen/qwen3.8-27b` (vision + текст), запасная `openai/gpt-oss-120b` при лимитах, `whisper-large-v3-turbo` (STT). Лимиты free-тарифа считаются на каждую модель отдельно (≈8000 токенов/мин, 200 000 токенов и 1000 запросов в сутки — это ≈90 постов в сутки на модель)
- **БД**: SQLite (нет файлов — бот хранит ссылки/метаданные, медиа остаются в Telegram)
- **Развёртывание**: Render (Docker, основной) или локально на ПК (Windows, автозапуск — резерв)
- Python 3.12 · aiohttp · aiohttp-socks

## Быстрый старт (локально)

```bash
git clone https://github.com/ShurikPozd/tg-saver-bot-cloud
cd tg-saver-bot-cloud
cp .env.example .env
```

Заполни `.env`:

```ini
BOT_TOKEN=телеграм_токен_бота        # @BotFather
API_ID=12345                          # my.telegram.org
API_HASH=hex_ключ                     # my.telegram.org
GROQ_API_KEY=gsk_...                  # console.groq.com/keys
# Только при локальном запуске из РФ (на зарубежном хосте оставить пустым):
GROQ_PROXY=socks5://127.0.0.1:10808  # api.groq.com из РФ напрямую даёт 403
```

Запуск:

```bash
docker compose up -d --build
```

## Запуск 24/7 (локально, Windows) — резерв

> ⚠️ Не держи локальный бот и Render-сервис запущенными одновременно: у них один
> `BOT_TOKEN`, но разные базы — сообщения непредсказуемо достаются то одному, то
> другому инстансу, и сохранения разъезжаются. Перед локальным запуском останови
> сервис на Render (и наоборот).

Бот держит постоянное соединение с Telegram по MTProto (Telethon). Транспорт задаётся
`TG_TRANSPORT` в `.env`:

- `socks` *(по умолчанию)* — SOCKS5 через локальный Xray (`TG_SOCKS_HOST=127.0.0.1`,
  `TG_SOCKS_PORT=10808`), тот же контур, что у ботов hh/demo;
- `mtproxy` — резерв через локальный MTProxy (`MT_PROXY_HOST=127.0.0.1`, `MT_PROXY_PORT=1080`);
- пусто/`direct` — напрямую (зарубежный хост/Render).

Groq API из РФ напрямую отдаёт 403 — поэтому в `.env` обязателен `GROQ_PROXY=socks5://127.0.0.1:10808`
(если его нет, `/api/chat` и категоризация падают с ошибкой соединения к прокси).

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
Copy-Item .env.example .env    # заполнить BOT_TOKEN, API_ID, API_HASH, GROQ_API_KEY
.\.venv\Scripts\pythonw.exe bot.py   # без окна консоли, лог в logs/bot.log
```

Логи пишутся в `logs/bot.log` (ротация 10 МБ × 5). Автозапуск при входе в систему и
перезапуск при падении — через Планировщик задач Windows.

> ⚠️ **Перезапуск бота — ТОЛЬКО через задачу** `\Bots\TgSaverBot`:
>
> ```powershell
> Start-ScheduledTask -TaskName "TgSaverBot" -TaskPath "\Bots\"
> ```
>
> **Не запускай `bot.py` вручную** (`Start-Process`, `pythonw bot.py` из консоли и т.п.):
> планировщик не видит ручной инстанс как «свой», считает бота остановленным и на
> ближайшем повторе (Logon + каждые 10 мин) поднимает **второй**. Два Telethon-клиента
> на один `.session` → `database is locked` → флап `/healthz`. У задачи стоит
> `MultipleInstancesPolicy=IgnoreNew` — при живом инстансе повтор задачи ничего не делает.
> Единственный легальный способ перезапустить: погасить процесс и дёрнуть задачу
> (`Get-ScheduledTask` → родитель `svchost` = планировщик, значит бот поднят правильно).

## Развёртывание на Render (основной хостинг)

> Сейчас бот работает на Render: `https://tg-saver-bot-cloud.onrender.com`
> (через него же расширение «Сводка комментариев YouTube» ходит в Groq по `POST /api/chat`).
> Free-тариф ограничен **750 ч/мес** на аккаунт — этого впритык хватает на один сервис 24/7.
> Если лимит кончится (как 2026-09-17), сервис встанет до начала следующего месяца —
> на это время переключайся на локальный запуск (см. раздел выше).
> Без входящих запросов free-сервис засыпает через ~15 мин; чтобы бот не спал,
> пингуй `GET /healthz` внешним монитором (например, UptimeRobot раз в 5–10 мин).

1. **Render → New → Web Service**, Runtime **Docker**, регион поближе к Telegram.
2. Переменные окружения из `.env` (на зарубежном хосте `MT_PROXY_*` и `GROQ_PROXY` не нужны).
3. Health check: `GET /healthz` на `PORT`.

Диск free-тарифа эфемерный: после перезапуска бот сам **восстанавливает базу** из последнего экспорта. Порядок источников: **GitHub-синк** (основной) → **канал-хранилище** (свежие снимки) → seed-файл.

Чтобы GitHub-синк работал, включи в переменных окружения:

```ini
GITHUB_TOKEN=ghp_...              # токен с правом write на backup-репозиторий
GITHUB_REPO=user/tg-saver-backups # репозиторий-хранилище бэкапов
GITHUB_BRANCH=main
GITHUB_PATH=backups               # папка внутри репозитория
```

Автоматические копии: **ежедневно (04:00 UTC)**, **каждые N сохранённых постов** (`backup_every_posts`, по умолчанию 5), **раз в 10 минут при любых изменениях** (перемещения, переименования, теги) и **перед остановкой сервиса** (SIGTERM при деплое/перезапуске Render) — тихие, файл в чат не присылается и **в канал-хранилище автоматически больше не отправляется** (только GitHub-синк + seed-файл). Экспорт по команде `/export` (или кнопке) присылает файл `tg_saver_export.json.gz` (содержимое gzip), обновляет GitHub-копию и кладёт копию в канал-хранилище. Информация о последнем бэкапе — команда `/info`.

## Мультиюзер

Каждый пользователь Telegram, написавший боту, получает **свой изолированный архив**: отдельный файл БД, свои категории, теги, папки и настройки. Никто не видит чужие сохранения — хоть в личке, хоть в общей группе (в группе каждый сохраняет в свой архив).

- При первом запуске бот **мигрирует** старую единую БД (`saved_items.db`) в личный архив владельца (`OWNER_ID` из `.env`) — данные никуда не пропадают.
- `OWNER_ID` также получает восстановление при пустой базе: **GitHub-синк → канал-хранилище → seed-файл**. Для остальных архив создаётся пустым автоматически.

## Команды

```
/categories  — папки и категории архива
/search      — поиск по тексту и дате
/stats       — статистика
/info        — информация о последнем бэкапе
/settings    — настройки
/dups        — найти дубли
/archive     — перенос старых постов в Архив
/export      — выгрузить архив (файл + GitHub-копия)
/help        — справка
```

Пересылай посты боту в личку — или добавь его в группу с правами и сохраняй сообщения оттуда.

## Тесты

```bash
python -m unittest discover tests
```

Проверяют чистку подвалов, хранение распознанного, лечение `file_ids`, устойчивость
цикла «бэкап → восстановление», поиск дублей и похожих постов, фильтр галлюцинаций Whisper.

## Проверки перед деплоем

GitHub Actions (`.github/workflows/tests.yml`) на каждый push компилирует модули и гоняет `python -m unittest discover -s tests`. Чтобы сломанный код не доезжал до бота, в Render включи **Settings → Build & Deploy → Auto-Deploy: After CI Checks Pass**.
